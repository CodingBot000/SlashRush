# Slash Rush 구현 완료 기준 게임 기획서

작성 시각: 2026-05-19 02:23:38 KST  
작성 기준: 현재 프로젝트에 실제 구현된 Godot 4.6.2 코드, 씬, 에셋, 테스트 스크립트  
보존 원본: `docs/report/slash_rush_planning_2026-05-15_to_2026-05-18.md`

이 문서는 원본 토론 문서를 수정하지 않고, 현재 구현된 게임을 제출 기준으로 재정리한 최종 기획서다. 원본 문서에 있던 제안, 미확정 항목, 구현 전제는 실제 코드와 다른 경우 현재 구현을 우선한다.

## 1. 게임 개요

`Slash Rush`는 모바일 가로 화면을 기준으로 만든 2D 사무라이 액션 러너다. 플레이어는 자동으로 달리는 사무라이를 직접 이동시키지 않고, 화면 오른쪽에서 다가오는 오브젝트를 보고 `Tap`, `Tap Tap`, `Hold`, 또는 아무 입력도 하지 않는 판단을 빠르게 수행한다.

핵심 플레이는 다음 흐름으로 구성된다.

```text
인트로 → 메인 메뉴 → 러너 60초 생존 → 보스전 → 승리/게임오버 결과
```

게임의 중심 재미는 반사신경만이 아니라 오브젝트 판별에 있다. 적은 베어야 하고, 좋은 아이템은 일반 상태에서는 베지 않고 지나가게 해야 한다. 피버 상태에서는 규칙이 완화되어 빠르게 공격하는 보상 구간으로 전환된다.

## 3. 전체 게임 흐름

### 3-1. 인트로

`IntroScene`은 로고와 `TAP TO START` 안내를 보여준다. 터치, 마우스 좌클릭, Space, Enter 입력으로 메인 메뉴로 이동한다. 배경은 `assets/background/intro/intro_background.png`, 로고는 `assets/ui/logo.png`를 사용한다.

### 3-2. 메인 메뉴

`MainMenu`는 다음 기능을 제공한다.

| 버튼 | 동작 |
|---|---|
| PLAY | `scenes/Main.tscn`으로 이동해 러너 게임 시작 |
| CHARACTER | 캐릭터 선택 프로토타입 화면으로 이동 |
| HOW TO | 조작법 카드 화면으로 이동 |
| 설정 아이콘 | 볼륨, 진동, 테스트용 무적 설정 팝업 열기 |

메인 메뉴 하단에는 저장된 누적 코인과 최고 점수가 표시된다.

### 3-3. 러너 스테이지

PLAY를 누르면 바로 러너 스테이지가 시작된다. 러너는 60초 동안 진행되며, 체력이 0이 되지 않은 상태로 60초를 버티면 보스 스테이지로 전환된다.

### 3-4. 보스 스테이지

보스전은 러너 스테이지의 점수, 코인, 남은 체력을 이어받는다. 보스 체력은 10이며, 패턴에 맞는 입력을 성공할 때마다 1씩 감소한다. 보스를 쓰러뜨리면 승리 결과가 표시된다.

### 3-5. 결과

결과 패널은 `VICTORY` 또는 `GAME OVER`를 표시한다. 결과 시 현재 점수, 이번 판 코인, 최고 점수가 표시되며, 최고 점수와 누적 코인은 `user://save.cfg`에 저장된다.

## 4. 입력 규칙

| 입력 | 구현 판정 | 사용처 |
|---|---:|---|
| Tap | 짧게 누르고 떼기 | 기본 적, 폭탄, 보스 기본 패턴 |
| Tap Tap | 첫 탭 후 0.25초 안에 두 번째 탭 | 빠른 적, 보스 양팔 내려찍기 패턴 |
| Hold | 0.45초 이상 누른 뒤 떼기 | 장갑 적, 보스 코어 차지 패턴 |
| No Input | 입력하지 않음 | 코인, 회복, 피버 오브, 보스 WAIT 패턴 |

입력 회복 시간은 일반 상태에서만 적용된다.

| 입력 | 회복 시간 |
|---|---:|
| Tap | 0.22초 |
| Tap Tap | 0.35초 |
| Hold | 0.45초 |

피버 중에는 입력 회복 시간이 무시되어 빠른 연속 공격이 가능하다. 피격 슬로우/경직 중에는 현재 입력이 초기화되고 새 공격이 막힌다.

PC 테스트 입력은 Space와 R이 구현되어 있다.

| 입력 | 동작 |
|---|---|
| Space | Tap / Tap Tap / Hold 판정 |
| R | 게임 재시작 디버그 |
| 마우스 좌클릭/터치 | HUD의 게임플레이 터치 영역을 통해 공격 입력 |

## 5. 플레이어 상태

| 항목 | 값 |
|---|---:|
| 시작 HP | 3 |
| 최대 HP | 3 |
| 피격 피해 | 1 |
| 피격 슬로우 | 0.4초 |
| 피격 중 배경 속도 | 10% |
| 피격 중 오브젝트 속도 | 0% |

HP가 0 이하가 되면 게임오버다. 단, 테스트용 무적이 켜져 있으면 데미지와 회복 처리는 유지하되 사망만 막는다.

플레이어 시각 상태는 `RUN`, `IDLE`, `DAMAGE`, `DEAD`로 구성된다. 러닝 애니메이션은 현재 `frame_01.png`부터 `frame_04.png`까지 4프레임 루프를 12FPS로 사용한다. 공격 시 칼집 스프라이트를 숨기고 slash 스프라이트를 짧게 표시한다.

## 6. 러너 오브젝트 규칙

| ID | 분류 | 처리 입력 | 성공 보상 | 실패/통과 처리 | 비고 |
|---|---|---|---:|---|---|
| `enemy_basic` | 적 | Tap | 점수 100, 피버 +6, 콤보 +1 | HP -1, 콤보 리셋 | 기본 허수아비 |
| `enemy_fast` | 적 | Tap Tap | 점수 150, 피버 +10, 콤보 +1 | HP -1, 콤보 리셋 | 붉은 유령 |
| `enemy_armor` | 적 | Hold | 점수 150, 피버 +10, 콤보 +1 | HP -1, 콤보 리셋 | 장갑/드럼형 적 |
| `bomb` | 위험물 | Tap | 점수 80, 피버 +4, 콤보 +1 | HP -1, 콤보 리셋 | 현재 구현에서는 피해야 할 물체가 아니라 베어야 하는 Tap 계열 위험물 |
| `coin` | 좋은 아이템 | 입력 없음 | 점수 +20, 코인 +20 | 일반 상태에서 베면 파괴 | 지나가게 두면 자동 획득 |
| `heal` | 좋은 아이템 | 입력 없음 | HP +1 | 일반 상태에서 베면 파괴 | HP가 가득 차면 `MAX` 표시 |
| `fever_orb` | 좋은 아이템 | 입력 없음 | 점수 +50, 즉시 피버 시작 | 일반 상태에서 베면 파괴 | 데이터상 fever 값은 있으나 현재 획득 시 즉시 피버 |

일반 상태에서 좋은 아이템을 베면 `BROKEN!`이 표시되고 콤보가 0이 되며 피버 게이지가 18 감소한다. 데미지는 받지 않는다.

Tap 대상에는 Tap Tap도 성공으로 인정된다. 예를 들어 기본 적이나 폭탄은 더블탭으로도 처리된다. 반대로 Tap Tap 대상에 Tap만 입력하면 실패가 아니라 `TAP TAP!` 안내만 표시된다. Hold 대상에 Tap만 입력하면 `HOLD!` 안내만 표시된다.

액션 판정 영역은 화면 좌측 하단 쪽 고정 구역이다.

```text
중심: (390, 610)
크기: 240 x 240
```

개발용 판정 가이드는 존재하지만 실제 플레이 화면에서는 숨겨져 있다.

## 7. 러너 스폰과 난이도

러너는 60초 고정 길이이며, 완전 랜덤이 아니라 시간 구간별 허용 오브젝트와 간격을 둔 스케줄 기반 스폰을 사용한다.

| 구간 | 시간 | 스폰 간격 | 위험 오브젝트 |
|---|---:|---:|---|
| opening_buffer | 0-8초 | 0.9-1.2초 | `enemy_basic`, `bomb` |
| basic_mix | 8-18초 | 0.75-1.0초 | `enemy_basic`, `bomb`, `enemy_fast` |
| input_pressure | 18-30초 | 0.65-0.9초 | `enemy_basic`, `bomb`, `enemy_fast` |
| armor_mix | 30-42초 | 0.7-1.0초 | 전체 위험 오브젝트 |
| high_pressure | 42-52초 | 0.55-0.8초 | 전체 위험 오브젝트 |
| final_wave | 52-60초 | 0.5-0.75초 | 전체 위험 오브젝트 |

아이템 스폰 예산과 제한은 다음과 같다.

| 아이템 | 예산/목표 | 제한 |
|---|---:|---|
| coin | 목표 10-14개, 최대 14개 | 좋은 아이템끼리 최소 2초 간격 |
| fever_orb | 최대 2개 | 18-26초, 42-52초 창에서 배치, 최소 16초 간격, 피버 종료 후 8초 차단 |
| heal | 최대 2개 | HP가 최대보다 낮을 때만 등장, 후보 시간 24/42/54초 근처, 최소 12초 간격 |

장갑 적은 30초 이전에 등장하지 않고, 장갑 적끼리는 앞뒤 간격을 확보한다. 빠른 적은 연속 압박이 과도해지지 않도록 바로 연속 배치를 피한다.

## 8. 점수, 코인, 콤보

점수는 오브젝트 성공 처리와 아이템 획득으로 증가한다. 현재 구현에서 콤보는 점수 배율을 직접 만들지 않고, 연속 성공 표시와 피드백 효과로 사용된다.

| 상황 | 점수 | 코인 | 콤보 |
|---|---:|---:|---|
| 적/폭탄 성공 처리 | 오브젝트 점수 | 변화 없음 | +1 |
| 코인 획득 | +20 | +20 | 유지 |
| 회복 획득 | +0 | 변화 없음 | 유지 |
| 피버 오브 획득 | +50 | 변화 없음 | 유지 |
| 실패/피격 | 변화 없음 | 변화 없음 | 0 |
| 좋은 아이템 파괴 | 변화 없음 | 변화 없음 | 0 |

코인은 러너 구간에서 획득한 값이 보스전과 결과 화면까지 이어진다. 결과 처리 시 이번 판 코인이 누적 코인에 더해지고 저장된다.

## 9. 러너 피버

러너 피버는 적 처치로 게이지를 쌓거나 피버 오브를 획득해서 발동한다.

| 항목 | 값 |
|---|---:|
| 최대 게이지 | 100 |
| 지속 시간 | 5.5초 |
| 배경 스크롤 배율 | 2.0x |
| 오브젝트 이동 배율 | 2.0x |
| 플레이어 러닝 애니메이션 배율 | 3.0x |
| 피버 러시 스폰 간격 | 0.12-0.22초 |
| 피버 종료 전 러시 중단 | 마지막 1.0초 |
| 종료 후 일반 스폰 회복 지연 | 0.8초 |

피버 중 러시 스폰은 다음 가중치를 사용한다.

| 오브젝트 | 가중치 |
|---|---:|
| `enemy_basic` | 75 |
| `enemy_fast` | 15 |
| `bomb` | 10 |

피버 중에는 장갑 적과 좋은 아이템이 러시 스폰에 포함되지 않는다. 피버 진입 시 기존 일반 오브젝트는 정리된다.

피버 중 규칙은 일반 상태와 다르다.

| 상황 | 피버 중 처리 |
|---|---|
| 적/폭탄 공격 | 입력 종류와 관계없이 성공 |
| 점수 | 적/폭탄 점수 2배 |
| 피버 중 미스/통과 | 데미지 없음, 보상 없음, 오브젝트 제거 |
| 코인 베기 | 코인 +20, 점수 +40 |
| 회복 베기 | HP가 부족하면 회복, HP가 가득 차면 코인 +20/점수 +40 |
| 피버 오브 베기 | 코인 +20, 점수 +40 |

피버 화면에서는 속도선, 버스트, 플래시 오버레이가 켜지고 HUD 중앙 상단에 `TAP!!` 안내가 강조된다.

## 10. 보스전

보스전은 러너 클리어 후 시작되는 두 번째 게임 구간이다. 플레이어는 왼쪽, 로봇 사무라이 보스는 오른쪽에 배치된다.

| 항목 | 값 |
|---|---:|
| 보스 HP | 10 |
| 보스 기본 성공 점수 | +200 |
| 보스 피버 성공 점수 | +400 |
| 보스 격파 보너스 | +500 |
| 보스 피버 최대치 | 100 |
| 보스 성공당 피버 획득 | +25 |
| 보스 피버 지속 시간 | 5.0초 |

보스 패턴은 보스 HP가 절반 이하가 되면 2페이즈로 전환된다.

| 페이즈 | 조건 | Tap | Tap Tap | Hold | Wait |
|---|---|---:|---:|---:|---:|
| 1페이즈 | HP 6-10 | 10 | 8 | 8 | 4 |
| 2페이즈 | HP 1-5 | 4 | 11 | 11 | 4 |

각 페이즈는 30개 패턴 덱을 만들고 셔플한 뒤 순환 사용한다.

| 패턴 | 요구 입력 | 제한 시간 | 보스 모션/큐 |
|---|---|---:|---|
| RIGHT_ARM_SLAM | Tap | 1.85초 | 원형 큐 1개 |
| BOTH_ARM_SLAM | Tap Tap | 2.0초 | 원형 큐 2개 |
| CORE_CHARGE | Hold | 2.2초 | 빠르게 반복되는 원형 큐 |
| WAIT | 입력 없음 | 1.8초 | 창 모양 큐 |

보스전에서 WAIT 패턴은 제한 시간 동안 아무 입력도 하지 않으면 성공이다. WAIT 중 입력하면 실패한다. Tap Tap과 Hold 패턴에서 Tap만 입력한 경우는 즉시 실패시키지 않고 패턴을 계속 유지한다.

성공 시 보스 HP가 1 감소하고 보스가 HIT 모션으로 흔들린다. 실패 또는 시간 초과 시 플레이어가 1 피해를 받는다. HP가 0이 되면 보스전 게임오버다.

보스 피버 중에는 패턴 큐가 숨겨지고, 어떤 공격 입력이든 보스에게 피해를 준다. 피버 중 패턴 시간이 끝나면 플레이어 피해 없이 다음 패턴으로 넘어간다.

## 11. 보스 시각 구조

`RobotSamuraiBoss`는 파츠 기반 Node2D 구조로 구현되어 있다.

```text
BodyPivot
HeadPivot
LeftArmPivot
RightArmPivot
CorePivot
ClothLeftPivot
ClothRightPivot
```

모션 상태는 다음과 같다.

```text
IDLE
ATTACK_WINDUP
ATTACK_STRIKE
ATTACK_RECOVER
STUN
HIT
DEFEATED
```

공격 타입은 현재 세 가지다.

```text
RIGHT_ARM_SLAM
BOTH_ARM_SLAM
CORE_CHARGE
```

원본 계획에 있던 `LEFT_ARM_SWEEP`은 현재 최종 구현에서는 사용하지 않는다. 대신 더블탭 패턴에 대응하는 `BOTH_ARM_SLAM`이 구현되어 있다.

보스는 기본 호흡, 머리/팔/천 흔들림, 코어 펄스, 공격 예비동작, 타격 흔들림, 패배 붕괴 모션을 가진다. 공격 판정 자체는 `BossStage`의 패턴 입력 판정이 담당하며, 보스 파츠 모션은 공격 힌트와 피드백 역할을 한다.

## 12. 배경과 화면 연출

러너 배경은 이미지 기반 패럴랙스와 바닥 루프로 구성되어 있다.

| 레이어 | 에셋 | 스크롤 계수 |
|---|---|---:|
| Sky | `sky_static.png` | 고정 |
| CloudLayer | `cloud_01.png` | 0.0128 |
| FarLayer | `far_mountains_01.png` | 0.24 |
| MidLayer | `mid_structures_01.png` | 0.58 |
| NearLayer | `near_foreground_01.png` | 1.12 |
| GroundLooper | `ground_tile_01.png` | 별도 고속 루프 |

바닥은 `GroundLooper`가 별도로 담당하며, 플레이어 기준선과 하단 시각 기준을 맞춘다. 이미지 로드 실패 시에는 폴리곤 기반 fallback을 생성한다.

보스전은 `boss_background.png`를 전체 화면 배경으로 사용하며, 전투 중 천천히 회전한다.

## 13. 이펙트와 피드백

현재 구현은 별도의 `EffectManager`라는 이름의 중앙 매니저 대신, 각 스테이지와 전용 유틸/팩토리가 이펙트를 처리한다.

| 기능 | 구현 |
|---|---|
| 오브젝트 파괴 | `SliceEffectFactory`가 텍스처 기반 물리 조각 2개 생성 |
| 조각 물리 | `SlicePiece`가 impulse, torque, gravity, lifetime 처리 |
| 아이템 부유 | `ObjectVisualEffectUtil.calculate_floating_spring_y` |
| 적 점프/스쿼시 | `ObjectVisualEffectUtil.apply_spring_jump_squash_stretch` |
| 피버 화면 연출 | `FeverImpactOverlay`의 속도선, 버스트, 플래시 |
| 피격 연출 | 플레이어 DAMAGE 스프라이트, 깜빡임, 슬로우, 히트스톱, 화면 흔들림 |
| 콤보 연출 | `ComboImpactPopup` 이미지/숫자 팝업 |
| 월드 텍스트 | 점수, MISS, BROKEN, HOLD 안내 등 Tween 팝업 |

원본 계획에 있던 `HoldChargeEffect` 전용 씬은 현재 구현되어 있지 않다. Hold 입력은 입력 판정과 플레이어 강공격 slash 크기 차이, 보스/오브젝트 큐로 표현된다.

## 14. UI/UX

### 14-1. HUD

HUD는 CanvasLayer로 구현되어 있고 게임 화면 전체 터치 영역도 함께 담당한다.

| UI | 표시 내용 |
|---|---|
| SCORE | 현재 점수 |
| 하트 | 현재 HP / 최대 HP |
| COMBO | 러너 콤보 |
| COIN | 이번 판 코인 |
| FEVER bar | 러너 피버 게이지 |
| BOSS bar | 보스 HP |
| Boss timer | 보스 패턴 제한 시간 |
| Feedback | FEVER, HIT, MISS, BOSS 등 |
| TAP!! | 러너 피버 중 입력 유도 |
| Pause | 일시정지 팝업 |

디버그용 무적 버튼과 피버 채우기 버튼은 코드상 존재하지만 기본값은 보이지 않음이다. 무적 상태 경고 라벨은 무적 플래그가 켜져 있을 때 표시된다.

### 14-2. HOW TO

HOW TO는 가로 스크롤 5카드 구조다.

| 카드 | 설명 대상 |
|---|---|
| TAP | `enemy_basic`, `bomb` |
| TAP TAP | `enemy_fast` |
| HOLD | `enemy_armor` |
| ITEMS | `coin`, `fever_orb`, `heal` |
| COMBO & FEVER | 콤보와 피버 |

각 카드는 실제 오브젝트 텍스처를 불러와 아이콘으로 표시한다. Back 버튼으로 메인 메뉴에 돌아간다.

### 14-3. Character Select

캐릭터 선택은 프로토타입으로 구현되어 있다.

| 카드 | 상태 |
|---|---|
| Player 1 | SELECTED |
| Player 2 | LOCKED |
| Player 3 | LOCKED |
| Player 4 | LOCKED |
| Player 5 | LOCKED |
| Coming Soon | COMING SOON |

카드는 가로 스크롤 방식이다. 현재 실제 캐릭터 교체, 해금, 구매, 저장은 구현하지 않는다. 잠긴 카드나 Coming Soon 카드를 누르면 안내 메시지만 표시된다.

### 14-4. 설정

설정 팝업은 다음 값을 `user://settings.cfg`에 저장한다.

| 설정 | 기본값 |
|---|---|
| 볼륨 | 100 |
| 공격 진동 | ON |
| 피격 진동 | ON |

테스트용 무적 토글도 설정 팝업에 노출되어 있다.

### 14-5. 일시정지와 결과

게임 중 Pause 버튼으로 일시정지가 가능하다. 팝업에는 `RESUME`, `QUIT`이 있다. QUIT은 메인 메뉴로 돌아간다.

결과 패널은 게임오버 시 사망한 플레이어 스프라이트를 어두운 dim 위에 유지해 실패 장면이 이어져 보이도록 처리한다.

## 17. 제출 기준 구현 확정 사항

원본 문서에서 미확정이거나 제안이었던 항목 중, 현재 구현 기준으로 확정된 내용은 다음과 같다.

| 항목 | 최종 구현 기준 |
|---|---|
| `bomb` 규칙 | Tap으로 처리해야 하는 위험 오브젝트. 지나치거나 잘못 처리하면 피해 |
| 피버 오브 | 일반 획득 시 즉시 러너 피버 시작 |
| 콤보 점수 배율 | 없음. 콤보는 표시/피드백 중심 |
| 러너 피버 | 5.5초, 점수 2배, 입력 회복 제거, 러시 스폰 |
| 보스전 | 체력/패턴/승패까지 구현됨 |
| 보스 더블탭 모션 | 원본의 왼팔 횡베기가 아니라 양팔 내려찍기 |
| 러닝 프레임 | 현재 4프레임 루프 사용 |
| EffectManager | 별도 이름의 전역 매니저 없음. 전용 클래스들로 분산 구현 |
| HoldChargeEffect | 전용 씬 없음 |
| 캐릭터 선택 | 시각 프로토타입만 구현, 실제 선택 저장 없음 |
