# 1. 게임 콘셉트

Slash Rush는 캐릭터가 화면 왼쪽에서 달리는 것처럼 보이지만 실제로는 배경, 바닥, 오브젝트가 오른쪽에서 왼쪽으로 이동하는 2D 액션 러너다. 플레이어는 복잡한 이동을 하지 않고, 화면 탭/롱탭 같은 매우 단순한 입력으로 앞에서 다가오는 대상을 처리한다.

> **한 줄 설명**  
> “수련 타깃은 베고, 먹어야 할 것은 참아라.” 짧은 판단과 시원한 절단 연출을 중심으로 한 검술 러너.

- 문화권에 고정되지 않는 제목과 구조를 사용한다. 사무라이, 중세 기사, 도끼전사, 로봇 검사 등 캐릭터 해금 확장이 가능해야 한다.

- 러닝 구간은 빠른 판단과 리듬감을 만든다. 보스전은 게임의 피날레이자 검술 판타지를 강화하는 짧은 미니게임으로 설계한다.

- 초기 버전은 모든 이미지를 갖추지 않아도 Godot 기본 도형, ColorRect, Polygon2D, Label, Line2D 등으로 동작해야 한다.

- 베기 성공 시 오브젝트가 두 조각으로 분리되고, 각 조각이 RigidBody2D 물리로 튀어 오르고 회전하며 떨어지는 연출을 최우선으로 구현한다.

# 2. 타깃 경험과 플레이 감정

| **목표 감정**  | **구현 방식**                                                             | **주의점**                                                            |
|----------------|---------------------------------------------------------------------------|-----------------------------------------------------------------------|
| 시원함         | 베기 성공 시 히트스톱, 검광, 화면 흔들림, 조각 물리 튕김을 즉시 보여준다. | 과한 이펙트로 입력 타이밍이 가려지면 안 된다.                         |
| 아차 싶은 실수 | 코인·회복·피버 아이템을 무심코 베면 파괴되어 보상을 못 받는다.            | 실수가 불공정하게 느껴지지 않도록 오브젝트 색과 아이콘을 명확히 한다. |
| 짧은 몰입      | 30~90초 안에 러닝 구간과 보스전을 끝낼 수 있게 한다.                      | 초기 버전에서 스테이지가 길면 반복감이 커진다.                        |
| 성장 기대      | 코인으로 캐릭터/무기 스킨을 해금하는 구조를 후속 확장으로 둔다.           | 프로토타입에서는 과금 구현이 아니라 해금 UI 더미 정도로 충분하다.     |

# 3. 핵심 플레이 루프

1.  캐릭터는 화면 왼쪽 고정 위치에서 달리는 애니메이션을 재생한다.

2.  바닥 타일, 배경 레이어, 오브젝트가 왼쪽으로 이동해 전진감을 만든다.

3.  오브젝트가 액션 존에 들어오면 플레이어는 베기/참기/탭탭/롱탭 중 하나를 판단한다.

4.  성공하면 점수, 콤보, 피버 게이지가 오른다. 실패하면 체력 감소, 아이템 파괴, 콤보 끊김이 발생한다.

5.  일정 거리 또는 오브젝트 수를 넘기면 러닝을 멈추고 보스전으로 전환한다.

6.  보스전에서 짧은 입력 패턴을 성공시키면 클리어, 실패하면 체력이 줄고 재도전 욕구를 만든다.

# 4. 입력 설계

| **입력**      | **모바일**              | **PC 테스트**                 | **게임 내 의미**                                 | **MVP 반영** |
|---------------|-------------------------|-------------------------------|--------------------------------------------------|--------------|
| 기본 탭       | 화면 탭                 | Space 또는 좌클릭             | 일반 베기 / 기본 공격 / 시작·재시작 확인         | 필수         |
| 탭탭          | 짧은 시간 안에 두 번 탭 | Space 2회 또는 좌클릭 2회     | 빠른 타깃 처리 / 보스 연속 패턴 대응             | 필수         |
| 롱탭          | 0.45초 이상 누르기      | Space 또는 좌클릭 길게 누르기 | 장갑 타깃·방어 자세 보스 대응                    | 필수         |
| 참기          | 입력하지 않음           | 입력하지 않음                 | 코인·회복·피버 아이템을 몸으로 획득              | 필수         |
| 방향 슬라이스 | 스와이프 또는 드래그    | 우클릭 드래그 또는 별도 키    | 향후 방향성 베기·퍼즐형 절단용. MVP에서는 예약만 | 보류         |

> **입력 복잡도 원칙**  
> 프로토타입에서는 탭, 탭탭, 롱탭, 참기만 쓴다. 슬라이드는 재미가 확실해진 뒤 추가한다. 초반부터 넣으면 조작 튜닝과 판정 설명에 시간이 많이 들어간다.

# 5. 러닝 구간 규칙

러닝 구간은 “보고 바로 판단하는” 구간이다. 캐릭터 이동, 점프, 회피를 넣지 않고 베기와 참기만으로 플레이하도록 제한한다. 이렇게 해야 하이퍼캐주얼의 직관성이 유지된다.

| **오브젝트** | **표현**                                | **정답 행동**                   | **실패 결과**          | **비고**                       |
|--------------|-----------------------------------------|---------------------------------|------------------------|--------------------------------|
| 일반 타깃    | 밀짚 수련 인형                          | 탭으로 베기                     | 체력 -1                | 가장 기본 타깃                 |
| 빠른 타깃    | 바퀴 달린 나무색 목각 인형              | 탭탭                            | 체력 -1                | 탭 1회만 하면 빗나감           |
| 장갑 타깃    | 나무 판을 방패처럼 붙인 회청색 목각 인형 | 롱탭                            | 체력 -1                | 차지 베기 학습용               |
| 코인         | 노란 원형                               | 베지 않고 접촉해서 획득         | 베면 파괴, 보상 없음   | 좋은 아이템의 대표             |
| 회복 아이템  | 초록 주먹밥/하트                        | 베지 않고 접촉해서 획득         | 베면 파괴, 회복 없음   | 하트 3칸까지만 회복            |
| 피버 오브    | 보라/파랑 구체                          | 베지 않고 접촉해서 획득         | 베면 파괴, 게이지 없음 | 피버 유도                      |
| 폭탄/위험물  | 검은 화약통                   | 탭으로 베거나 피버 중 자동 처리 | 체력 -1                | 좋은 아이템과 색을 확실히 구분 |

- `enemy_fast`는 플레이어보다 약 20% 크게 렌더링한다.

# 6. 베기 판정과 절단 연출

- 캐릭터 앞에 투명한 액션 존을 둔다. 오브젝트가 이 영역에 들어온 순간부터 입력을 판정한다.

- 일반 베기 판정은 액션 존 중앙 기준 약 0.25~0.35초를 기본값으로 잡고, 체감에 따라 조정한다.

- 베기 성공 시 원본 오브젝트를 제거하고, 좌/우 또는 상/하 조각 2개를 생성한다.

- 조각은 RigidBody2D로 만들고 서로 다른 방향의 impulse와 torque impulse를 부여한다.

- 조각 수명은 1.0~1.5초로 제한한다. 화면 밖으로 나가거나 시간이 지나면 queue_free 한다.

- 히트스톱 0.04~0.07초, 검광 Line2D/Polygon2D, 작은 화면 흔들림을 넣어 쾌감을 만든다.

| **연출 요소**            | **권장값**                   | **의도**                          |
|--------------------------|------------------------------|-----------------------------------|
| Hit stop                 | 0.05초                       | 베는 순간의 손맛 강화             |
| 조각 상승 impulse        | Vector2(±120~220, -250~-420) | 두동강 조각이 위로 튀는 느낌      |
| 조각 회전 torque impulse | ±2500~6000                   | 빙글빙글 도는 쾌감                |
| 화면 흔들림              | 0.06초, 3~6px                | 타격감 보강. 과하면 피로함        |
| 검광                     | 0.08~0.15초                  | 베기 방향과 성공 여부를 즉시 전달 |

> **중요한 구현 방향**  
> 실시간으로 이미지를 잘라내는 고급 절단 시스템은 MVP에서 제외한다. 처음에는 미리 정한 도형 조각 또는 동일 스프라이트를 마스크/폴리곤으로 표현한다. 핵심은 “실제로 자르는 기술”이 아니라 “잘린 것처럼 보이는 즉각적인 반응”이다.

# 7. 맵과 패럴랙스 배경

실제 캐릭터는 크게 이동하지 않는다. 바닥과 배경이 이동하며, 비슷한 맵 조각을 이어붙여 긴 맵처럼 보이게 한다. 프로토타입에서는 3~5개의 반복 세그먼트를 만들고, 세그먼트 끝이 화면 왼쪽 밖으로 나가면 오른쪽 끝에 다시 배치한다.

| **레이어**   | **움직임**              | **예시**         | **프로토타입 표현**   |
|--------------|-------------------------|------------------|-----------------------|
| 하늘/먼 배경 | 가장 느림               | 구름, 먼 산      | ColorRect + 원/다각형 |
| 중간 배경    | 중간 속도               | 성벽, 나무, 기둥 | 반복 사각형 실루엣    |
| 가까운 배경  | 빠름                    | 풀, 돌, 표지판   | 작은 도형 반복        |
| 바닥         | 러닝 속도와 동일        | 흙길, 돌길       | 타일 사각형 반복      |
| 오브젝트     | 바닥보다 약간 동일/빠름 | 수련 타깃, 아이템, 위험물 | Area2D/Node2D 기반    |

# 8. 피버 시스템

- 피버 게이지는 수련 타깃과 위험물을 정확히 처리하거나 피버 오브를 먹으면 증가한다.

- 게이지가 100이 되면 4초 동안 피버가 자동 발동되거나, 프로토타입에서는 즉시 발동으로 단순화한다.

- 피버 중에는 수련 타깃과 위험물은 자동 절단되고, 좋은 아이템은 자동 획득된다.

- 피버 중 점수 배율을 2배로 적용한다. 단, 보스전에는 피버를 가져가지 않는다.

| **행동**                 | **게이지 변화** | **점수**       |
|--------------------------|-----------------|----------------|
| 일반 타깃 정확히 베기    | +6              | +100           |
| 빠른/장갑 타깃 정확히 처리 | +10             | +150           |
| 코인 획득                | +0              | +20            |
| 피버 오브 획득           | +25             | +50            |
| 좋은 아이템을 베어 파괴  | +0              | +0 / 콤보 끊김 |
| 피버 중 자동 처리        | 소모 중         | 기본 점수 x2   |

# 9. 보스전 설계

보스전은 러닝 구간이 끝난 뒤 진행되는 짧은 입력 미니게임이다. 길고 복잡한 전투가 아니라, 5~8회의 명확한 패턴을 처리하면 끝나는 피날레로 설계한다.

| **보스 패턴** | **화면 신호**              | **정답 입력** | **실패 결과**         |
|---------------|----------------------------|---------------|-----------------------|
| 빈틈 노출     | 흰색 섬광/검 아이콘 1개    | 탭            | 플레이어 체력 -1      |
| 연속 공격     | 검 아이콘 2개              | 탭탭          | 플레이어 체력 -1      |
| 방어 자세     | 방패/갑옷 아이콘           | 롱탭          | 플레이어 체력 -1      |
| 페이크        | 붉은 X 또는 늦게 뜨는 신호 | 참기          | 성급히 누르면 체력 -1 |

- 보스 체력은 5칸, 플레이어 체력은 러닝 구간에서 남은 체력을 그대로 사용한다.

- 각 패턴은 0.8~1.4초 간격으로 등장한다. 후반으로 갈수록 판정 시간을 조금 줄인다.

- 보스 격파 시 큰 절단 연출 또는 화면 전체 검광을 보여준다.

- MVP에서는 보스 1종만 구현한다. 캐릭터 해금과 별개로 보스 확장은 후순위다.

# 10. UI/UX

| **화면**  | **필수 UI**                       | **설명**                              |
|-----------|-----------------------------------|---------------------------------------|
| 타이틀    | Slash Rush 로고, Tap to Start     | 처음에는 텍스트만으로 충분            |
| 러닝      | 체력, 점수, 콤보, 피버 게이지     | 화면 상단에 작고 명확하게 배치        |
| 보스전    | 보스 HP, 플레이어 HP, 입력 아이콘 | 러닝 UI보다 입력 신호를 크게          |
| 결과      | 점수, 최고 점수, 획득 코인, Retry | 즉시 재도전 흐름                      |
| 해금 더미 | 캐릭터 카드 3~5개                 | 과금/해금 확장 가능성을 보여주는 수준 |

- 플레이어 체력은 숫자 대신 하트 3개로 표시한다. 회복 아이템은 빈 하트가 있을 때만 채우며, 이미 3칸이면 더 회복되지 않는다.

- 코인 획득 표시는 코인 개수가 아니라 코인 값 누적이다. 코인 1개의 기본 값은 20이며, 코인을 먹을 때마다 `COIN` 값이 20씩 오른다.

- 좋은 아이템은 노랑/초록/보라 계열, 수련 타깃/위험물은 밀짚색/나무색/회청색/검정 계열로 나눈다.

- 텍스트 없이도 이해되도록 아이콘과 색을 강하게 쓴다.

- 좋은 아이템을 베면 “BROKEN!” 같은 짧은 피드백을 띄워 실수를 웃기게 만든다.

# 11. 캐릭터와 수익화 확장 방향

Slash Rush라는 제목은 특정 문화권에 묶이지 않는다. 기본 캐릭터가 사무라이에서 중세 기사로 바뀌어도 게임 규칙은 유지된다. 캐릭터 해금은 추후 수익화 포인트가 될 수 있으므로, 캐릭터 데이터 구조를 초기에 분리해둔다.

| **해금 요소** | **예시**                              | **게임 영향**               | **주의점**                        |
|---------------|---------------------------------------|-----------------------------|-----------------------------------|
| 캐릭터 스킨   | 기사, 사무라이, 바이킹, 로봇 검사     | 외형 중심. 공격 판정은 동일 | 과금 캐릭터가 유리해 보이면 안 됨 |
| 무기 스킨     | 검, 도끼, 광선검, 대검                | 검광 색/절단 이펙트 변경    | 판정 범위는 동일                  |
| 피니시 연출   | 보스 마무리 검광, 승리 포즈           | 소장 욕구 강화              | 프로토타입에서는 더미 카드만      |
| 코인 해금     | 플레이로 얻은 코인으로 기본 스킨 해금 | 반복 플레이 동기            | 광고/IAP는 제출 후 고려           |

# 14. MVP 완료 판정

- 모바일 가로모드 기준 1280x720 화면에서 UI와 게임 영역이 잘 보인다.

- PC에서는 Space 또는 좌클릭으로 기본 탭이 동작한다.

- 캐릭터는 실제로 달리지 않아도 배경/바닥/오브젝트 이동으로 전진감이 난다.

- 수련 타깃이나 위험물을 정확히 처리하면 두 조각이 물리로 튀고 회전하며 사라진다.

- 좋은 아이템을 베면 파괴되어 획득하지 못한다.

- 피버 게이지와 피버 자동 처리 구간이 작동한다.

- 러닝 구간 종료 후 보스전으로 전환되고, 탭/탭탭/롱탭 패턴으로 승패가 결정된다.

- 결과 화면에서 점수와 Retry가 표시된다.

# 15. 참고 기술 기준

아래 항목은 개발지시서에서 Godot 구현 기준으로 사용한다. 실제 값은 Godot 버전과 프로젝트 상태에 맞춰 Codex가 조정할 수 있다.

- ProjectSettings: display/window/size/viewport_width, viewport_height, stretch mode/aspect, display/window/handheld/orientation

- InputMap: 모바일 탭, PC Space, 마우스 좌클릭을 같은 액션으로 묶기

- Parallax2D: 카메라 대비 다른 속도 이동으로 2D 깊이감 구현

- RigidBody2D: 베어진 조각에 one-time impulse와 torque impulse 적용
